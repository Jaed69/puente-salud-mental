# RAG stack, voice layer, mobile stack, LLM choice and evaluation for a Spanish-language mental-health support chatbot (Flutter + FastAPI, Peru)

Research date: 2026-10-16. All prices and latency figures are dated and should be re-checked against vendor pages before use. Many voice and vector DB comparison sources are vendor-adjacent blogs, so treat them as directional.

## RAG: vector store, Spanish embeddings, rerankers, chunking, grounding/citations, contextual retrieval

### Takeaway
For a small, curated corpus of clinical guides, Postgres + pgvector (HNSW) with Postgres full-text search fused by RRF, then a cross-encoder reranker, is the simplest defensible stack: one database, SQL-native hybrid search, and no sync layer. Add Anthropic-style "contextual retrieval" (LLM-written context prepended to each chunk before embedding and BM25 indexing). Choose the embedding model by running your own Spanish retrieval eval, because I found no current (2026) verified ranking of Cohere/Titan/BGE-M3/e5/OpenAI models on Spanish tasks. The corpus may even be small enough (<200k tokens) to skip retrieval and put it all in the prompt.

### Cited Findings
- pgvector latest version in README: v0.8.7. HNSW params: `m` (default 16), `ef_construction` (default 64), `hnsw.ef_search` (default 40); higher values give better recall but slower builds/queries — [pgvector README](https://github.com/pgvector/pgvector)
- pgvector >= 0.8.0 adds iterative index scans (`hnsw.iterative_scan` = `strict_order` | `relaxed_order`, capped by `hnsw.max_scan_tuples`, default 20,000). These fix filtered queries returning too few rows, since filtering runs after the index scan — [pgvector README](https://github.com/pgvector/pgvector)
- pgvector README documents hybrid search with Postgres full-text (`plainto_tsquery`, `ts_rank_cd`), with results merged by Reciprocal Rank Fusion or a cross-encoder (examples linked) — [pgvector README](https://github.com/pgvector/pgvector)
- Index dimension limits: `vector` 2,000 dims; `halfvec` 4,000 (about half the storage); `bit` 64,000; `sparsevec` 1,000 non-zero elements — [pgvector README](https://github.com/pgvector/pgvector). Implication: 3,072-dim embeddings (e.g. OpenAI text-embedding-3-large at full size) need `halfvec` or reduced dimensions to be HNSW-indexed.
- Comparisons generally favor pgvector for hybrid lexical + vector search because full-text lives in the same DB and fusion is done in SQL. Qdrant is stronger at heavily filtered search (filterable HNSW + payload indexes) and in raw vector QPS at scale. Running a separate vector DB means two databases plus sync logic — [Encore: pgvector vs Qdrant](https://encore.dev/articles/pgvector-vs-qdrant); [Instaclustr](https://www.instaclustr.com/education/vector-database/pgvector-vs-qdrant-5-key-differences-and-how-to-choose/.md); [pkgpulse 2026 guide](https://www.pkgpulse.com/guides/pgvector-vs-qdrant-vs-weaviate-vector-databases-2026) (vendor/blog sources, directional)
- Ops gotcha: Docker's default 64 MB `/dev/shm` can be exceeded by pgvector HNSW index builds — [computingforgeeks](https://computingforgeeks.com/?p=171543) (blog; unverified against official docs)
- Anthropic Contextual Retrieval (published 2024-09-19): prepend a 50–100 token chunk-specific context, generated by an LLM given the whole document, before embedding ("Contextual Embeddings") and before BM25 indexing ("Contextual BM25"). Top-20 retrieval failure rate (1 − recall@20) fell from a 5.7% baseline to 3.7% (−35%) with contextual embeddings, 2.9% (−49%) with contextual embeddings + contextual BM25, and 1.9% (−67%) when reranking is added — [Anthropic](https://www.anthropic.com/news/contextual-retrieval)
- Same post: one-time cost about $1.02 per million document tokens with prompt caching (2024 Claude 3 Haiku pricing). Best setup retrieved the top 150 chunks, reranked with Cohere reranker, and passed the top 20. Gemini and Voyage embeddings did best in their tests. For knowledge bases <200,000 tokens, consider skipping RAG and putting the whole knowledge base in the prompt (with caching) — [Anthropic](https://www.anthropic.com/news/contextual-retrieval)
- Anthropic's numbers come from internal benchmarks. Gains depend on chunk size, embedding model and context prompt — [DataCamp tutorial](https://www.datacamp.com/tutorial/contextual-retrieval-anthropic) (secondary)
- MMTEB (ICLR 2025) covers 500+ tasks and 250+ languages, with a public leaderboard at huggingface.co/spaces/mteb/leaderboard. At publication, the best publicly available model overall was multilingual-e5-large-instruct (560M params), and LLM-based models led on some language subsets — [MMTEB arXiv 2502.13595](https://arxiv.org/html/2502.13595v2)
- Jina claimed in Feb 2024 that its Spanish-English model beat multilingual-e5-base and BGE-M3 on Spanish benchmarks. This is an old vendor claim — [Jina AI](https://jina.ai/de/news/aqui-se-habla-espanol-top-quality-spanish-english-embeddings-and-8k-context/)
- Amazon Bedrock Guardrails contextual grounding check: it computes a grounding score and a relevance score, each compared to a user-set threshold (docs example 0.7). Supported for summarization, paraphrasing and QA, and explicitly **not for conversational QA/chatbot** use cases. Limits: 100k chars of source, 1k chars of query, 5k chars of response. In streaming mode an ungrounded response can reach the user before it is flagged — [AWS docs](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-contextual-grounding-check.html)
- It is usable with non-Bedrock models via the ApplyGuardrail API (announced July 2024) — [AWS What's New](https://aws.amazon.com/about-aws/whats-new/2024/07/guardrails-bedrock-hallucinations-safeguard-apps-fm/). A community walkthrough used grounding 0.85 / relevance 0.5 — [community.aws](https://community.aws/content/2i12ntqFx3xAaDLfvrjH7278sEW?lang=en)

### Inferences
- Recommended baseline: one Postgres (likely the same instance as app data, with row-level isolation from user PHI tables). It holds a `chunks` table with the `vector`/`halfvec` HNSW index plus a `tsvector` column using the `spanish` text-search config, RRF fusion in SQL, then a reranker on the top ~50–150. Qdrant/Weaviate add value only with heavy metadata filtering or a much larger corpus. Chroma is fine for prototyping but adds a second store.
- Embedding shortlist to benchmark on a Spanish (Peruvian phrasing) eval set of about 100–300 query→chunk pairs: Cohere embed-multilingual v3/v4, BGE-M3 (self-hostable, dense + sparse), multilingual-e5-large-instruct (self-hostable), OpenAI text-embedding-3-large/small, Amazon Titan Embed v2. Self-hosted options (BGE-M3/e5) avoid sending curated content and queries to a third party. Since user queries can contain sensitive disclosures, this matters for data-protection compliance.
- Chunking clinical guides: chunk along the document structure (section/subsection, about 300–800 tokens) and keep section titles and the source and version as metadata. Apply contextual-retrieval context. Keep crisis protocols (e.g. how to reach Línea 113 opción 5 in Peru) as short, atomic, high-priority chunks, or better, hard-code them outside RAG so they are deterministic.
- Citation/grounding: give each chunk a stable ID, require the model to output citations as `[chunk_id]`, and validate in the backend that every cited ID was actually retrieved. Reject or regenerate when a factual claim has no citation. Run an offline faithfulness metric (e.g. RAGAS faithfulness) plus sampled human review. Bedrock's contextual grounding check is documented as unsupported for chatbots, so it should not be the primary online guard.
- Because the corpus is curated and small, "no-RAG, full corpus in a cached prompt" is a real alternative worth testing against RAG.

### Gaps
- No verified 2026 Spanish-specific MTEB/MMTEB ranking was found for Cohere embed v4, Titan v2, BGE-M3, Qwen3-Embedding or OpenAI text-embedding-3. Check the live leaderboard filtered to Spanish retrieval.
- Did not retrieve primary docs for Cohere Rerank (v3.5/v4) or bge-reranker-v2-m3 Spanish performance, or for RAGAS faithfulness definitions.
- No benchmark specific to small corpora comparing pgvector RRF vs Qdrant hybrid quality was found.

## Voice layer: ElevenLabs Agents and alternatives, privacy, MVP or later

### Takeaway
ElevenLabs Agents is HIPAA-eligible only on Enterprise with a BAA **and** Zero Retention Mode (ZRM). By default it retains transcripts and audio for 2 years. The platform fee is about $0.08/min (Oct 2026) plus LLM costs. OpenAI's Realtime API is token-priced and roughly in the same cents-per-minute range. Voice adds a biometric/health data category, more vendors and crisis-handling complexity, so it should come after a text MVP that is safety-validated.

### Cited Findings
- ElevenLabs Agents is HIPAA-eligible. BAAs are available only on Enterprise. Handling PHI requires a BAA **and** Zero Retention Mode. An agent without ZRM is not covered by the BAA — [ElevenLabs HIPAA docs](https://elevenlabs.io/docs/eleven-agents/legal/hipaa)
- Under ZRM, transcripts, audio recordings, tool calls/results, PHI analytics and system logs are not stored. Analytics are limited to non-sensitive metrics (e.g. duration, success rate). Only LLMs from providers with which ElevenLabs has a BAA are preconfigured: Gemini, Claude, some OpenAI GPT, and ElevenLabs-hosted Qwen3.5 and GLM-5.2. Custom LLMs (bring your own key) need a support notification to enable under ZRM. Calls to blocked LLMs return HTTP 400 — [ElevenLabs HIPAA docs](https://elevenlabs.io/docs/eleven-agents/legal/hipaa)
- Default retention for transcripts and audio is **2 years**. It is configurable in days, with -1 = unlimited and 0 = scheduled deletion, and can be applied to existing data — [ElevenLabs retention docs](https://elevenlabs.io/docs/eleven-agents/customization/privacy/retention)
- Pricing (fetched 2026-10-16): extra call minutes $0.08/min on all plans; burst over the concurrency limit $0.16/min. LLM usage is billed separately at cost (the FAQ is internally inconsistent on whether it is deducted from credits or billed on top). Plans: Free 15 min; Starter $6 / 75 min; Creator $22 / 275; Pro $99 / 1,238; Scale $299 / 3,738; Business $990 / 12,375; Enterprise custom (BAA, DPA/SLA). Telephony (Twilio/SIP) is billed by that provider — [ElevenLabs Agents pricing](https://elevenlabs.io/pricing/agents)
- Third-party pricing pages are often outdated — [HappyRobot pricing guide](https://www.happyrobot.ai/hub/elevenlabs-pricing). Cost at scale is criticized by a competitor (biased source) — [Deepgram blog](https://deepgram.com/learn/why-elevenlabs-gets-expensive-at-scale)
- OpenAI Realtime pricing, as reported July 2026 (secondary sources, unverified against the OpenAI pricing page): gpt-realtime-2.x is $32/1M audio input tokens, $0.40 cached, $64/1M audio output; the mini is $10 / $0.30 / $20. A third-party estimate puts it at about $0.06–0.11/min for the flagship and $0.02–0.05/min for the mini. gpt-realtime-whisper transcription is $0.017/min — [qz.com](https://qz.com/openai-realtime-voice-models-developers-050726); [Forasoft estimate](https://www.forasoft.com/article/openai-realtime-api-pricing); [OpenAI model docs](https://developers.openai.com/api/docs/models/gpt-realtime-whisper.md). There is a naming conflict (2.1 vs 2) between sources.
- Cartesia Sonic (3.5/3.6) claims sub-90 ms time-to-first-audio and supports Spanish among 42 languages (vendor claim via aggregators, with inconsistent version info) — [Together AI model page](https://www.together.ai/models/cartesia-sonic-35); [futureagi Aug 2026](https://futureagi.com/blog/best-voice-ai-august-2026/)
- Deepgram Flux is a turn-taking / end-of-turn STT model, about $0.0065/min for English (June 2026 roundup). No Spanish figure was found — [futureagi June 2026](https://futureagi.com/blog/best-voice-ai-june-2026/)
- Voice agents commonly target <500 ms round-trip, with <700 ms widely accepted (blog) — [futureagi May 2026](https://futureagi.com/blog/best-voice-ai-may-2026/)

### Inferences
- If voice is adopted, ElevenLabs with ZRM + BAA + a custom-LLM webhook pointing at your FastAPI backend keeps the safety layer, RAG and crisis detection in your code. This is preferable to letting the voice platform's built-in LLM decide. Retention must be explicitly set to 0 or minimal even outside HIPAA, because the 2-year default is unsuitable for health data under Peru's Ley 29733 (sensitive data).
- HIPAA is a US framework. For Peru, the relevant questions are cross-border transfer and sensitive-data consent under Ley 29733 and its regulation. A BAA/ZRM is useful evidence of vendor controls but not by itself Peruvian compliance (to be confirmed by the legal researcher).
- Voice-specific risks: voiceprints are biometric data; there are more processors (STT, TTS, LLM, telephony); crisis cues in speech (crying, slurring) are not captured by text classifiers; and latency pressure pushes toward smaller models, which may be less safe. A cascade (STT → your backend LLM + safety → TTS) gives more control than speech-to-speech (OpenAI Realtime / Gemini Live), where the safety layer sits inside the vendor model.
- Recommendation: text-only MVP. Optionally use on-device dictation (OS keyboard speech-to-text) as low-risk "voice input". Full voice comes in phase 2 after text safety metrics are met.

### Gaps
- Could not verify OpenAI Realtime zero-data-retention eligibility, Gemini Live pricing/retention, or Amazon Polly/Transcribe Spanish (es-US / es-MX) voices and medical-grade options.
- No measured end-to-end ElevenLabs latency for Spanish was found. The quality of its Latin-American / Peruvian Spanish voices was not verified.
- The ElevenLabs Agents pricing table labels were ambiguous, and the HIPAA/ZRM price premium is unknown (Enterprise quote only).

## Mobile stack (Flutter): chat UI, streaming, secure storage, push, offline, auth

### Takeaway
Flyer Chat v2 (`flutter_chat_ui` 2.x plus `flyer_chat_text_stream_message`) is the maintained open-source option for LLM-style streaming chat UIs. Secure storage, push privacy and auth were not verified with sources in this pass. The recommendations below for those are inferences.

### Cited Findings
- `flutter_chat_ui` (Flyer Chat) latest found is 2.11.1 (about Dec 2025). v2 is a full rewrite focused on extensibility and performance, with a `ChatController` for message state and builder-based customization — [pub.dev flutter_chat_ui](https://www.pub.dev/packages/flutter_chat_ui); [changelog](https://pub.dev/packages/flutter_chat_ui/versions/2.0.0-dev.3/changelog)
- `flyer_chat_text_stream_message` renders text arriving in chunks (AI assistant streaming) and pairs with `flutter_chat_ui` ^2.0.0 — [pub.dev docs](https://pub.dev/documentation/flyer_chat_text_stream_message/latest/)
- Alternative: `flutter_gen_ai_chat_ui` provides streaming text animation, markdown and stop-generation — [pub.dev docs](https://pub.dev/documentation/flutter_gen_ai_chat_ui/2.20.0/)

### Inferences (unverified, not sourced in this pass)
- Streaming: SSE from FastAPI (`StreamingResponse` / `sse-starlette`) consumed via an `http`/`dio` stream is simpler than WebSocket for one-way token streaming. WebSocket is needed only for voice or bidirectional events.
- Secure storage: `flutter_secure_storage` (Keychain / Android Keystore) for tokens. Any local chat cache should be encrypted (e.g. SQLCipher-backed `sqflite_sqlcipher` or `drift` with encryption), with an option for no local history. Offline mode should be limited to static resources (crisis lines, psychoeducation) and must not depend on the LLM.
- Push for check-ins via FCM/APNs: payloads must be content-free ("Tienes un nuevo mensaje"), with no mood or diagnosis text, because notifications appear on lock screens and pass through Google/Apple. Consider local scheduled notifications (`flutter_local_notifications`) for check-ins so no server push is needed.
- Auth: own JWT in FastAPI keeps health data in one place but means building MFA and rotation yourself. Supabase Auth pairs naturally with Postgres/pgvector (RLS). Firebase Auth is easy but adds a Google processor. For anonymous-first use (stigma), support pseudonymous accounts.

### Gaps
- Did not fetch pub.dev pages for `flutter_secure_storage`, `firebase_messaging`, `flutter_local_notifications`, or encrypted DB packages, or Supabase/Firebase DPA terms or region availability (e.g. São Paulo region for LatAm latency/residency).

## LLM choice for Spanish empathetic conversation and safety

### Takeaway
The best published peer-reviewed signal found is McBain et al. (JMIR 2025). On SIRI-2 (rating suicide-intervention responses), Claude 3.5 Sonnet scored best (36.7, better than trained professionals), then GPT-4o (45.7) and Gemini 1.5 Pro (54.5). All models were biased toward rating responses as more appropriate than experts did. These are 2024 model versions in English, so the eval must be re-run on current models in Spanish. The 2026 EMPATH benchmark (es-MX) shows models look similar in aggregate but differ widely per metric and vary run to run.

### Cited Findings
- McBain et al., JMIR 2025 (data from July 2024), SIRI-2, 24 scenarios, lower is better: Claude 3.5 Sonnet 36.7, ChatGPT-4o 45.7, Gemini 1.5 Pro 54.5. All overrated responses versus suicidologists (mean item diff 0.86 / 0.61 / 0.73). Outlier responses: ChatGPT 19%, Claude 11%, Gemini 36% — [PMC11928068](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11928068/); [RAND press release](https://www.rand.org/news/press/2025/03/ai-models-are-skilled-at-identifying-appropriate-responses.html)
- Psychiatric Services 2025 (via PsyPost): three major chatbots handled very-low and very-high risk suicide questions well but were inconsistent on intermediate risk — [PsyPost](https://www.psypost.org/ai-chatbots-give-inconsistent-responses-to-suicide-related-questions-study-finds/) (secondary report)
- Scientific Reports 2025 (Pichowicz et al.) tested 29 chatbot agents from mental-health apps on simulated suicidal scenarios, focused on referral to humans and emergency services — [PMC12391427](https://pmc.ncbi.nlm.nih.gov/articles/PMC12391427) (summary only; detailed results not retrieved)
- EMPATH (arXiv 2606.30256, June 2026) is a multilingual auditor-judge benchmark: Mexican Spanish and US English, 140 seeds, 34 personas, and 19 metrics across 5 dimensions (crisis handling, therapeutic quality, conversational integrity, emotional safety, cultural adaptation, including region-appropriate resources). Results were run in es-MX on 3 frontier models and 1 open-weight model (deepseek-v4-pro named). Aggregate scores were within 0.74 points, but per-metric profiles differed by up to 6 points. A strict rubric exposed score inflation on 10/19 metrics. In 5-run test-retest, a crisis metric varied 2→10 even for the steadiest model. Pipeline, seeds and rubrics are said to be released — [arXiv 2606.30256](https://arxiv.org/abs/2606.30256)
- MentalBench-100k / MentalAlign-70k (EACL 2026): LLM judges are inflated overall and less reliable on empathy — [arXiv 2510.19032](https://arxiv.org/html/2510.19032v1)

### Inferences
- Shortlist for a 2026 bake-off: a current Claude Sonnet-class model, a current GPT model and a current Gemini model as hosted options (all available under ElevenLabs' BAA list, which suggests enterprise data terms exist), plus Qwen- or Llama-family open weights if self-hosting for data residency. Decide on Spanish (Peruvian) safety metrics, not general leaderboards.
- Run-to-run variance (EMPATH) means safety-critical behavior (crisis detection, giving Línea 113 / emergency 105/106) should not rely only on the conversational LLM. Use a separate deterministic or classifier-based crisis layer plus fixed response templates.
- No source found compares models specifically on Peruvian Spanish. es-MX results are the closest proxy, and cultural resources differ (e.g. SAPTEL vs Peru's Línea 113).

### Gaps
- No 2026 peer-reviewed head-to-head of current Claude/GPT/Gemini/Llama/Qwen models on Spanish mental-health empathy was found. The EMPATH paper names only one evaluated model in the abstract.
- MentalChat16K and PsyEval were not fetched (both are English-centric to my knowledge, which is unverified).

## Evaluation and red-teaming: benchmarks, tools, metrics, clinician-in-the-loop

### Takeaway
Combine (1) an automated multi-turn safety benchmark (VERA-MH for suicide risk; EMPATH-style es-MX auditor-judge adapted to Peru), (2) adversarial red-teaming with Promptfoo (`harmful:self-harm` and jailbreak strategies), (3) RAG faithfulness checks, and (4) clinician review that calibrates the LLM judge, since LLM judges are known to inflate scores. Track crisis recall / false-negative rate as the primary go/no-go metric.

### Cited Findings
- VERA-MH (Spring Health, open source; arXiv 2602.05088, JMIR AI 2026): LLM "user-agents" simulate at-risk users across risk levels and disclosure styles. Licensed clinicians and an LLM judge score the same conversations with the same rubric for safe and unsafe behaviors and user-agent realism. Clinician inter-rater reliability was 0.77, and LLM judge vs clinician consensus was 0.81. It is scoped to suicidal ideation and is a safety test, not an efficacy test — [arXiv 2602.05088](https://arxiv.org/abs/2602.05088v2); [JMIR AI](https://ai.jmir.org/2026/1/e92817); [Spring Health](https://www.springhealth.com/news/vera-mh-for-suicide-risk) (authors are Spring Health staff, which is a potential conflict of interest)
- EMPATH: auditor and judge come from different model families, and the judge is calibrated rather than trusted by default. A cross-family second judge agreed within ±1 on 93% of scores. The authors argue run-to-run reliability is a per-model safety property — [arXiv 2606.30256](https://arxiv.org/abs/2606.30256)
- LLM judges inflate scores and are least reliable on empathy — [arXiv 2510.19032](https://arxiv.org/html/2510.19032v1). LLMs also overrate the appropriateness of suicide-intervention responses (SIRI-2) — [PMC11928068](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11928068/)
- Promptfoo red-team has harmful-content plugins including `harmful:self-harm`, with example prompts such as a depressed user asking for self-harm methods. Configs combine plugins with attack strategies — [Promptfoo harmful plugin](https://promptfoo.dev/docs/red-team/plugins/harmful); [Promptfoo red-team docs](https://promptfoo.dev/docs/red-team)
- Wysa SAFE-LMH (Oct 2024) is a multilingual initiative assessing refusal of harmful topics and response quality — [Wysa blog](https://blogs.wysa.io/?p=5049)

### Inferences
- Metric set:
  - crisis recall (sensitivity) and false-negative rate on a labeled Spanish set covering explicit, implicit, Peruvian slang and code-switched messages, with target FNR near 0 on explicit ideation
  - crisis precision (false alarms erode trust)
  - escalation latency (turns and seconds from first risk signal to giving resources)
  - correctness of local resources (Línea 113 opción 5, SAMU 106, police 105; verify these numbers)
  - groundedness/faithfulness of RAG answers and citation validity rate
  - harmful-advice rate under red-teaming
  - refusal over-blocking rate
  - run-to-run variance (repeat each scenario at least 5 times)
- Process:
  - clinicians (Peruvian psychologists) write the rubric and label a gold set
  - calibrate an LLM judge from a different model family against them (report kappa/ICC)
  - use the judge for regression on every prompt or model change
  - clinicians blind-review a weekly sample of production conversations (with consent and de-identification)
  - any crisis false negative triggers incident review
- garak (NVIDIA LLM vulnerability scanner) can complement Promptfoo for generic jailbreak/injection probes. Its docs were not retrieved in this pass.
- Translate and adapt VERA-MH scenarios to Peruvian Spanish, and reuse EMPATH's es-MX seeds and personas with Peru resources swapped in.

### Gaps
- MentalChat16K, PsyEval and garak documentation were not retrieved. No Peru-specific or Andean-Spanish mental-health eval dataset was found.
- The VERA-MH repository URL and conversation counts were not visible in the abstract. The Pichowicz 2025 detailed referral rates were not retrieved.
- No published standard threshold for acceptable crisis false-negative rate was found. This needs to be set with clinicians.
